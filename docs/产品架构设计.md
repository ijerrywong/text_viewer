# 微信「纯文本阅读器」产品架构设计

> 版本 v1.0 · 配套文件：`../AGENTS.md`（硬约束）、`Edge-Cases-清单.md`（边界情况）、`WorkBuddy-构建说明书.md`（构建指令）

---

## 1. 背景与问题定义

AI 时代纯文本（Markdown / HTML / TXT / JSON / CSV / 日志 / 源码）会爆炸式增长，并以**文件**形式在微信里传输。但：

- 手机系统默认无法优雅预览 Markdown（正文+标题+代码+表格）。
- AI 生成的**自包含 HTML 长文档**（书、文章、PDF/PPT 转写）不是网页，是"静态文档"，但手机浏览器打开体验差、且很多人不装浏览器。
- TXT 存在**编码问题**（GBK 乱码）、大文件卡顿问题。
- 微信是中国大陆人人在用、且是主力文件传输工具。

**产品定位**：一个微信小程序，作为"微信里的文本/文档查看器"，纯本地、零后端、开箱即用。

### 1.1 明确非目标（Non-Goals）
- **不是**浏览器：不加载外部资源、不执行 JS、不渲染真实网页。
- **不是**编辑器：只读，不改文件。
- **不是**云盘/同步工具：无账号、无服务器。
- **不做**二进制 Office/PDF 的原生渲染：`.docx/.pdf/.pptx` 交给微信自带 `wx.openDocument` 预览或提示"暂不支持"。

## 2. 需求

### 2.1 功能需求（按优先级）
| 优先级 | 能力 | 说明 |
|---|---|---|
| P0 | 从微信聊天选择文件 | `wx.chooseMessageFile` 选 1..N 个文件（保底入口） |
| P0 | **剪贴板粘贴长文本** | AI 时代最高频场景：从 Claude/ChatGPT 复制大段 Markdown 直接渲染。仅用户点击时读取，默认不落盘（ADR-9） |
| P0 | TXT 渲染 | 编码自适应 + 手动切换 + 分页/虚拟滚动 |
| P0 | Markdown 渲染 | 标题/列表/表格/代码块/引用/图片/链接/任务列表 |
| P0 | HTML 渲染（自包含文档） | 消毒 + 内联 CSS 子集 + base64 图片 |
| P0 | 阅读体验 | 字号/行高/字体、深色/浅色/护眼主题 |
| P0 | 阅读进度 | 记住上次文件与滚动位置 |
| P1 | 目录 (TOC) | md/html 标题提取 + 锚点跳转 |
| P1 | 全文搜索 + 高亮 | 大文档性能可用 |
| P1 | 代码高亮 | 常见语言，懒加载 |
| P1 | 多文件队列 | 一次选多个，左右/标签切换 |
| P2 | 数学公式 | LaTeX/KaTeX（可选） |
| P2 | CSV/JSON 美化视图 | 表格/折叠树 |
| P2 | 分享转发 | 文件或"打开方式"引导 |
| P3 | 导出/书签/批注 | 远期，不在 MVP |

### 2.2 非功能需求（NFR）
- **隐私**：文件字节不出本机。
- **离线**：无网络依赖。
- **性能**：≥10MB 文件可用；低端机不崩溃；首屏 < 2s。
- **兼容**：iOS/Android 真机一致；基础库低版本降级。
- **体积**：主包 < 2MB，总包 < 20MB。
- **安全**：恶意 HTML 无执行面、无钓鱼跳转。
- **可维护**：格式解析器与渲染器解耦，可增删格式。

## 3. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                        入口层 (Entry)                         │
│  冷启动/热启动 · 场景识别 · chooseMessageFile · 分享/参数进入  │
└───────────────────────────────┬──────────────────────────────┘
                                │ 原始文件(file, name, size, tempPath)
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                      文件接入层 (Intake)                       │
│  适配器：chat-file / launch-scene / share                     │
│  · 复制 temp → USER_DATA_PATH（防失效）                       │
│  · 文件名清洗 · 去重 · 生成 stable id · 元数据登记             │
└───────────────────────────────┬──────────────────────────────┘
                                │ 本地持久化文件路径 + 元数据
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                   识别层 (Detect)                             │
│  ① 类型识别：扩展名 + 魔数(magic bytes) + 内容嗅探             │
│  ② 编码识别：BOM → meta charset → 字节启发式 → 默认 UTF-8     │
│  ③ 分流决策：txt / md / html / 其它纯文本 / 不支持             │
└───────────────────────────────┬──────────────────────────────┘
                                │ format + encoding + 分块读取策略
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                     解析层 (Parse)                            │
│  txtParser → mdParser → htmlParser(+sanitize) → 其它Parser     │
│  输出统一 IR（见 §5）· 大文件走分块/Worker · 图片抽取落盘       │
└───────────────────────────────┬──────────────────────────────┘
                                │ IR 分片 (chunks)
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                     渲染层 (Render)                           │
│  虚拟滚动容器 + 块渲染器（段落/标题/代码/表格/图片/公式）       │
│  主题/字号/字体 · 图片懒加载 · 代码高亮 · 目录 · 搜索高亮       │
└───────────────────────────────┬──────────────────────────────┘
                                │ 交互事件
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                     状态与存储 (Store)                        │
│  阅读进度 · 设置 · 最近文件 · 文件缓存 LRU · 索引(进度/目录)    │
└──────────────────────────────────────────────────────────────┘
```

**数据流主线**：入口拿到文件 → 落盘登记 → 识别类型+编码 → 解析成 IR → 分片交给虚拟滚动渲染 → 交互回写进度。

**核心解耦原则**：`格式解析器` 与 `渲染器` 通过统一 IR 解耦；`文件来源` 通过 Intake 适配器解耦。新增一种格式只加一个 Parser，不改渲染层。

## 4. 关键架构决策（ADR）

### ADR-1 本地优先、零后端
- **决策**：不做任何服务端。
- **备选**：云端转码/渲染（把文件上传服务器转 HTML 再下发）。
- **权衡**：云端能处理更大文件、更强渲染，但引入隐私风险、服务器成本、内容合规、离线不可用、审核复杂。本地优先完全满足"纯文本查看"这一核心，且是差异化卖点（隐私）。**采纳本地**，云端仅作远期可选项。
- **代价**：大文件/重型渲染受设备性能限制 → 用分块+虚拟化+降级缓解（ADR-5）。

### ADR-2 统一文档模型 IR
- **决策**：txt/md/html 都先转成同一种块级 IR，渲染层只认 IR。
- **备选**：每格式一套独立渲染组件。
- **权衡**：统一 IR 让渲染、搜索、目录、主题、虚拟滚动只实现一次；代价是 HTML 的任意 CSS 布局会"有损"（复杂样式被归一化）。**采纳 IR**，复杂 HTML 降级"阅读模式"（提取正文）。
- **IR 形态**：
```js
Block =
  { type:'heading', level:1..6, text, id }
  | { type:'paragraph', children:Inline[] }
  | { type:'code', lang, text, raw }
  | { type:'list', ordered, items:[{children:Inline[], depth}] }
  | { type:'table', header:[], rows:[[Inline]] }
  | { type:'blockquote', children:Block[] }
  | { type:'image', src, alt, w, h }   // src 已落盘为本地临时路径
  | { type:'hr' }
  | { type:'math', tex, display }
Inline = { text } | { code } | { bold } | { italic } | { link:{href,internal} } | { image } | { strike } | { br }
```

### ADR-3 渲染引擎选择：mp-html 打底 + 自研预处理层
- **决策**：
  - HTML：**`mp-html` 打底 + 自研预处理层**（Tailwind 展开 / CSS 变量求值 / 伪元素合成 / 视口钳制 / 脚本降级），预处理在送入 mp-html **之前**完成。
  - Markdown：`mp-html` 的 markdown 插件，或 `towxml`（GFM/公式/高亮更全）——**Phase 2 用样例集实测后定案**。
  - TXT：自研 `scroll-view` 虚拟列表（可控性最强）。
- **备选 A**：`web-view` 加载本地 HTML。
- **备选 B**：**全自研** HTML tokenizer + CSS 层叠引擎（在 JS 里实现浏览器层叠算法子集，把 `<style>` 规则算成每个节点的 inline style）。
- **权衡**：
  - `web-view` → **弃用**。个人主体根本不可用（微信不开放业务域名给个人主体，无申诉通道），且它只能加载 https 域名、无法稳定加载本地文件。
  - **全自研 → 弃用为默认方案，但保留为补充层**。它的诱人之处在于能力上限高：小程序 WebView 渲染层本质是浏览器内核，`flex`/`grid`/圆角/阴影/渐变全都有效，真正的障碍只是"`<style>` 选择器无法作用于小程序节点"，把层叠计算搬进 JS 即可绕开。但代价是数周工作量，且要重踩一遍 mp-html 已经踩过的容错坑（未闭合标签、实体解码、属性引号形态）。**mp-html 本身已内置简易 CSS 解析器**（标签/class/id 选择器），基础场景已覆盖。
  - 因此采纳**折中**：用成熟库承担解析与容错，把独特价值（AI 文档特有的 Tailwind / CSS 变量 / 伪元素问题）加在预处理层。
- **执行纪律**：**Phase 3 开始前必须用真实 AI 文档样例集实测 `mp-html` 的 `<style>` 支持程度**，结论写入 `docs/verify-notes.md`，据此确定自研层边界。**不得凭想象决定全自研或全依赖。**
- **代价**：复杂 CSS（绝对定位、动画、多栏）无法 1:1 还原 → 接受"文档语义优先于像素级还原"。所有 JS 行为（图表、Mermaid、reveal.js 翻页）永久性不可用，靠 §ADR-10 的可见降级对冲。

### ADR-3.1 保真度的物理上限（必须让决策者知情）
- **事实**：个人主体 + 无 `web-view` 的组合下，AI 生成 HTML 的还原上限是**结构完整 + 静态样式约 70–85%**。这是物理限制，不是工程投入能突破的。
- **反悔成本**：若将来要追求像素级保真，唯一出路是升级为企业/个体工商户主体 + 备案域名 + `web-view`。而**小程序主体不可变更**，必须重新注册 AppID，用户、数据、评价全部不迁移。
- **结论**：若对保真度的期待高于 85%，应在写第一行代码前重新决定主体，而非在 Phase 3 验收时才发现。

### ADR-4 编码识别与解码
- **决策**：内置解码器，识别顺序 BOM → meta → 启发式 → UTF-8，**必带手动切换**。
- **备选**：只支持 UTF-8，乱码时提示用户转码。
- **权衡**：GBK/GB18030 是大陆 txt 的常态，不支持则产品废一半；内置解码体积可控（码表约几百 KB，进分包）。**采纳内置**。真机 `TextDecoder` gbk 不可靠，用 `text-encoding` polyfill 或精简码表自实现。
- **代价**：编码探测存在误判 → 手动切换兜底（产品级必需）。

### ADR-5 大文件策略
- **决策**：按体积分层——
  - `< 1MB`：一次性读 + 全量解析渲染。
  - `1MB ~ 10MB`：分块读 + 全量解析(Worker) + 虚拟滚动。
  - `> 10MB`：分块读 + **渐进解析/渲染**，先看开头，滚动时按需解析。
  - `> 50MB`：降级"纯文本分页阅读"（不解析语法，按页浏览）。
- **备选**：一律全量加载。
- **权衡**：全量简单但大文件必崩/卡死；分层最大化可用性。**采纳分层**。
- **实现要点**：`FileSystemManager.readFile({filePath, position, length, success})` 分块；解析入 `Worker`（compute 密集不卡 UI）；渲染用固定行高虚拟列表。

### ADR-6 HTML 安全消毒
- **决策**：解析阶段强制消毒（白名单标签/属性），外链点击→确认→复制。
- **规则**：剥离 `script/iframe/object/embed/form/base/link@import/meta[refresh]`、所有 `on*` 事件属性、`style` 里的 `expression/url(javascript:)`、`href/src` 里的 `javascript:/vbscript:`。图片只允许 `data:image/` 与本地临时路径。
- **权衡**：安全性是底线，宁可误杀不可放过；富交互/脚本本就不是目标（自包含文档无 JS）。

### ADR-7 分包策略
- **决策**：主包 = 入口 + TXT 渲染 + 识别核心；`pkg-markdown`、`pkg-html`（含 mp-html/高亮/公式/GBK 码表）进分包；按文件类型懒加载对应分包。
- **权衡**：分包让主包 < 2MB 达标；代价是首次打开 md/html 有一次分包加载（<1s，可接受，可预下载）。

### ADR-8 图片策略（HTML/Markdown 内嵌图）
> ⚠️ 部分取代：下方「**网络图片默认关闭**」一条已被 **ADR-13**（2026-08-27）取代为**默认开启**。
> 其余内容（base64 抽取落盘、阈值、相对路径占位）**继续有效**。原文保留为历史推理记录。
- **决策**：base64 图片 → 解析时抽取 → 写 `USER_DATA_PATH` 临时文件 → IR 里 `image.src` 指向本地路径；超阈值（如单图 >5MB、总量 >50MB）跳过并占位。
- **备选**：直接把 `data:image/...;base64,` 交给 `<image>` 组件（该组件确实支持 data URI）。
- **权衡**：备选方案技术上可行，但**会直接撞上 `setData` 单次 1MB 上限**——AI 生成的 HTML 常内嵌数 MB 的 base64 图，把 base64 字符串塞进 setData 等于把整张图经逻辑层→Native→视图层传三次，轻则卡顿重则数据超限渲染失败。**落盘换成本地路径后，setData 只传一个几十字节的路径**，且可懒加载、可缓存、可复用。**采纳落盘**，配 LRU 清理。
- **网络图片**：`<image>` 组件的 `src` **不受合法域名白名单限制**（只有 `wx.request`/`downloadFile` 受限），网络图技术上可正常显示。但加载外链图会向第三方暴露用户 IP 与阅读行为 → **默认关闭，设置中可开启，并明确说明隐私影响**。硬禁止会让引用图床的 Markdown 大面积丢图，不可取。
- **相对路径图片**：单文件 md/html 无随行资源，必然失败 → 占位块 + 原始路径文本，**且不改变已计算的块高度**（否则虚拟滚动偏移错乱）。

### ADR-9 入口策略：三入口分层，不押注单点
- **决策**：`chooseMessageFile`（保底）+ 剪贴板粘贴（高频）+ 聊天素材打开 scene 1173（体验上限，需验证）。
- **备选**：只做 `chooseMessageFile`。
- **权衡**：
  - **scene 1173 能力真实存在**（`app.json` 声明 `supportedMaterials`，启动参数经 `forwardMaterials` 拿 `{type,name,path,size}`，官方列举支持 `.txt`/`.html`/`.csv` 等）。它能让用户在聊天里直接点文件打开，是体验上限所在。但 **`.md` 是否受支持、个人主体是否有限制、上线前能否验证**都待确认，且**上线后入口才出现**。故**不得作为主流程依赖**。
  - **剪贴板是被低估的第一入口**：AI 时代大量流转的不是文件而是"AI 吐出的一大段 Markdown"，手机上无处渲染。零文件零权限零等待。仅在用户明确点击时读取（iOS 有系统提示）。
- **代价**：三入口增加 Intake 层复杂度 → 用适配器模式解耦（`chat-file` / `clipboard` / `launch-material`），共用后续管线。

### ADR-10 AI 文档特有的样式失效与可见降级
- **决策**：内置 Tailwind 类名**规则生成器**；所有无法渲染的内容给可见降级卡片，不留空白。
- **备选**：忽略 Tailwind（假设 AI 文档都内联 CSS）。
- **权衡**：AGENTS.md §1 原本假设"CSS 内联或 `<style>` 内嵌"，**与现实不符**——相当高比例的 AI 文档引用 `cdn.tailwindcss.com` 只写类名。小程序里脚本不执行 + 域名不通 = **样式全部归零，页面塌成一堆左对齐裸文本**。这是 AI 生成 HTML 的最高频失败模式，忽略它会导致 Phase 3 验收时才暴露。
  用**规则生成器**（正则解析 `p-4` / `bg-slate-50` / `grid-cols-3` 等模式）而非穷举查表，体积可控在 20KB，仅在检测到 Tailwind 时异步加载。
- **代价**：Tailwind 类名覆盖不可能 100%，取高频子集；生成器需随 Tailwind 版本演进维护。
- **降级可见性原则**：用户看到"这里有张图表但显示不了"，远好于看到一片空白而怀疑文件损坏。

### ADR-11 阅读进度的存储模型
- **决策**：进度存 **`{fileId, blockIndex, ratio}`**（块索引 + 块内比例），**不存 `scrollTop` 像素值**。
- **备选**：存滚动像素位置（直觉方案）。
- **权衡**：存像素**会实际出 bug**——字号、行距、页边距、主题任一变化，像素位置立即失效；虚拟滚动下块高度还会在渲染时动态修正，像素基准根本不稳定。存块索引则天然不受字号影响，恢复时直接跳到该块，用预估高度构建上方占位即可。
- **代价**：恢复位置的精度是"块级"而非"像素级"，块内偏移靠 ratio 近似。对阅读场景完全够用。

### ADR-12 目标场景收窄：手机端临时阅读
> 状态：已定案（2026-08-27）。本条是 ADR-13 / ADR-14 的上位依据。

- **决策**：目标场景明确收窄为——**用户人在手机上、无电脑可用、有份纯文本现在必须读、读完立刻切走**。功能取舍一律以「**缩短从想读到读到的路径**」为判据，**不追求电脑端阅读器的功能完整度**。
- **情境特征**（四条，每一条都在否决东西）：**被迫的**（非主动选择）、**一次性的**（不积累）、**会被打断的**（随时切走）、**低耐心的**（不配置、不学习）。
- **备选**：做成功能完整的通用文本阅读器（多文件队列、资料库、跨文件全文检索、高保真渲染）。
- **权衡**：备选路线的每一项都隐含假设用户会「**积累**」和「**配置**」，而临时场景下用户两样都不做。按功能完整度排序，资源会流向低频 job；按路径长度排序，改文案与调入口位置的收益反而高于新增功能。
- **据此定的取舍**：
  - 剪贴板入口提到首屏视觉主位。原 `entry-primary` 给了 `chooseMessageFile`，**与 AGENTS.md §1.1 自述的优先级不一致**（该节明写"剪贴板是 AI 时代最高频场景，应放首屏显眼位置"）。
  - **跨文件全文搜索暂缓**。检索 job 的前提是「用户积累了一堆」，与本场景直接矛盾。真实需求更可能是「回到刚才那份」——由 `recent` 首条即可满足，代价差一个数量级。
  - **HTML 保真度优化暂缓**。ADR-3.1 已定 70–85% 为物理上限，且本场景只要求「知道上面写了啥」，不要求还原原貌。
  - 多文件队列（Edge-Cases A2）由 P1 降级。
  - **默认值质量 > 可调项数量**。用户不会进设置页，首次打开时的默认字号/行距/主题**即是全部体验**。
  - 切出再切回必须**原地**。ADR-11 的块索引方案为「跨冷热启动恢复」设计，但本场景的高频用途是**秒级**的（回条微信再切回来）；用户对十秒后回来"跳了一下"的感知远比对跨天恢复敏锐，需真机验证 `onShow` 不产生位置偏移。
- **代价**：放弃重度用户。
- **重估触发条件**：若用户行为显示出「积累」倾向（`recent` 长期贴近 `MAX_RECENT`、同一文件被反复打开、用户主动询问检索能力），本决策需重新评估。
- **反悔成本**：低。本决策主要指导**不做什么**，暂缓项不产生代码债。

### ADR-13 隐私约束的场景化放宽
> 状态：已定案（2026-08-27）。**取代 ADR-8 中"网络图片默认关闭"的部分**。依据 ADR-12。

- **决策**：微信传输的文本文件私密性普遍不高，隐私不再作为首要卖点。具体两项：① **网络图片默认开启**（原 ADR-8 为默认关闭）；② 首屏隐私文案下沉，把 hero 位让给 job 语言。
- **备选**：维持隐私优先叙事。
- **权衡**：
  - ADR-8 把网络图片默认关闭的**唯一理由是隐私**（加载外链图会向第三方暴露用户 IP 与阅读行为）。该理由在本场景下不成立，而代价是实打实的——Markdown 引用图床极常见，默认关闭导致**大面积丢图**。
  - 首屏 hero badge「本地解析 · 零上传 · 隐私安全」占据用户最初 3 秒的判断位。用户在那 3 秒要回答的是「**这能解决我现在的问题吗**」，而不是「我该不该担心」。隐私是过审的护身符和差异化底牌，但对最高频 job 是无效弹药。
- **⚠️ 明确未解锁的：本决策不解锁云端。** ADR-1 的「零后端」有四条理由，隐私仅其一：
  | ADR-1 的理由 | 本决策是否解除 |
  |---|---|
  | 隐私风险 | ✅ 解除 |
  | 服务器成本 | ❌ 仍在 |
  | ICP 备案 / 内容审核合规 | ❌ 仍在，**对个人主体是硬约束** |
  | 离线可用 | ❌ 仍在 |

  且 AGENTS.md §6.5「微信禁止无资质的网盘类小程序」与内容私密性无关，不因本决策松动。
- **保留的底线**：**本地解析、零网络请求的技术事实不变**，本决策只调整叙事权重与图片默认值。提审说明与 `docs/隐私说明.md` 的全部承诺**继续有效**。
- **代价**：网络图片默认开启后弱网下有加载等待，须配「加载失败给占位」而非无限转圈；少数确有隐私诉求的用户（工作合同、体检报告、简历）需自行关闭开关。
- **反悔成本**：零。开关本就存在，翻默认值即可。
- **实施时须同步**：`AGENTS.md` §2.4 网络图片条目、本文 ADR-8 网络图片段（已加取代标注）、settings 默认值。

**实施记录（2026-08-27，分支 `feat/adr-13-scene-relax`）**

三项决策落地之外，实施时撞出两个「翻默认值」本身带出来的问题，一并处理：

| 发现 | 为什么必须一起做 |
|---|---|
| **老用户到不了新默认值** | `saveSettings` 写的是整个 settings 对象，用户只要动过任意一项设置，旧的 `networkImages:false` 就在本地存储里，之后 `Object.assign(DEFAULT_SETTINGS, saved)` 永远是 saved 赢。不配迁移的话，本决策对已装用户等于没发生。已加一次性迁移（`app.js` `migrateSettings`，版本号 `_mv`）。**代价：无法区分「用户主动关的」和「继承了旧默认值」——旧默认本就是关，两者在存储里长得一模一样。按 ADR-13「少数隐私诉求用户自行关闭」承担这个代价。** |
| **门控只覆盖 HTML** | `gateNetworkImages` 原先只在 reader 的 html 分支里调用，**Markdown 的图床外链根本没被门控住**——而引用图床的恰恰以 Markdown 居多。默认关闭时这是"关了也没关掉"，默认开启后性质变了：开关是隐私用户**唯一**的关掉方式，它必须真的关得掉。已把门控移到 `_finalizeRender`（覆盖全格式，且在 `createLayout` 之前——占位与真图高度不同），并补上「改开关当场生效」「切回缓存文档按当前设置重新门控」两条路径。 |

首屏三处文案改动：hero badge 换 job 语言、隐私说明下沉为页尾脚注、粘贴卡片补上 E9 要求的「仅在你点它时读一次，不上传」小字（隐私说明 §5.2 的遗留项，顺手清掉）。

页尾脚注不能只写「不上传」就完事：**网络图片默认开启后，「不联网」对用户已经不是准确说法**——`<image>` 会由用户设备直接向图床发起加载。脚注写明这一点并指出关掉的去处。同口径同步了 `docs/隐私说明.md`、`docs/提审说明.md`。

回归：`tests/test-network-images.js`（默认值 / 迁移 / md 门控 / reader 接线 / 首屏文案，27 条）。

### ADR-14 不做网页浏览（否决"用网址阅读"）
> 状态：已定案（2026-08-27）。依据 ADR-12、ADR-1、ADR-6。

- **决策**：**不增加任何「输入或点击网址 → 在小程序内浏览网页」的能力。** 链接相关需求改由「**把链接交还给微信**」解决。
- **提出的理由**：「网址也属于 HTML 文件，在阅读范围内」。
- **前提纠正（记录在案，因为这个直觉一定会再次出现）**：**网址不是文件。** 文件是已在本机的字节，网址是一个需要**去取**的地址。产品的能力边界不在「能否渲染 HTML」（自研 tokenizer 已解决），而在「**字节从哪来**」——现有三入口的共同点是**字节由用户送入**。从「接收」改为「获取」，跨的是一整条平台管制线。
- **备选与否决理由（三堵墙，任意一堵足以否决）**：
  1. **`wx.request` 抓网页** → 受**合法域名白名单**限制：只能请求预先在后台配置的、已 ICP 备案的 https 域名，数量有硬上限。**无法覆盖全网**，接口层面物理不通。
  2. **`web-view` 加载** → 个人主体不可用（AGENTS.md §2.3 已定）。**且换主体亦无解**：`web-view` 只能加载**自己配置的业务域名**，不是任意网站。
  3. **自建代理抓取后从自有域名下发** → 同时违反 ADR-1（零后端），且构成**浏览器类 / 内容分发小程序**，与 §6.5 所禁网盘类同一逻辑，过审不了。
- **⚠️ 这不是权衡，是无路**：即使付出 ADR-3.1 所述的换主体代价（小程序主体不可变更 → 重注册 AppID → 用户/数据/评价全部不迁移），**本功能依然做不到**。不要把它误当成"值不值得"的取舍题。
- **采纳的替代解法**（同一个 job，成本差一个架构）：
  | 做法 | 说明 |
  |---|---|
  | **链接清单面板** | 遍历 IR 汇总全文链接。数据现成——`href` 已在 IR 的 `Inline.link` 与渲染层 `dataset` 中（见 `reader.js` `onLinkTap`） |
  | **显示域名而非完整 URL** | 60 字符的 URL 读不出信息；`github.com` / `arxiv.org` 能让用户一眼判断。纯字符串解析，零网络 |
  | **一键复制全部链接** | 用户切到微信粘贴，由**微信内置浏览器**打开——这才是本需求在本架构下的正解 |
  | **改 `onLinkTap` 文案** | 从解释限制（"小程序无法直接打开外部链接"）改为指路（"已复制，切到微信粘贴即可打开"） |
- **为什么替代解法在本场景下够用**：ADR-12 定义的场景中用户**本就要切出去**，「离开」是预期动作而非代价。电脑上「不想离开当前页」是真痛点，手机临时场景里不是。
- **安全要求**：链接清单集中展示**不降低 ADR-6 的消毒标准**。`javascript:` / `vbscript:` / `data:text/html` 不得出现在清单中，或须显式标记——集中列表反而更容易让人放松警惕点下去。
- **代价**：无法服务「就在这儿把网页读了」的需求。
- **反悔成本：极高，不建议。** 零网络请求是提审说明与 `docs/隐私说明.md` 全套承诺的技术基础（当前 `grep wx.request|downloadFile|web-view` 零命中）。一旦架构中出现网络请求，整套合规叙事与"每条承诺附可核验代码位置"的体系全部作废。

## 5. 模块职责与接口

| 模块 | 职责 | 关键对外接口 |
|---|---|---|
| `intake` | 统一文件来源（适配器） | `resolveLaunch(options)`（含 scene 1173 的 `forwardMaterials`）/ `chooseFromChat(count)` / `fromClipboard()` / `copyToUserDir(temp)` |
| `detect` | 类型+编码 | `sniff(buffer, filename) → {format, encoding, confidence}` |
| `parse/txt` | txt→IR | `parseTxt(text|chunk) → Block[]` |
| `parse/md` | md→IR | `parseMarkdown(md) → Block[] + toc` |
| `parse/html` | 消毒+预处理+html→IR | `parseHtml(html) → {blocks, images[], toc, degraded[]}` |
| `parse/html/pre` | **AI 文档预处理层** | `expandTailwind(nodes)` / `resolveCssVars(nodes)` / `synthPseudo(nodes)` / `clampViewport(nodes)` / `degradeScripts(nodes)` |
| `sanitize` | HTML 消毒 | `sanitize(nodes, policy) → safeNodes` |
| `render` | 虚拟滚动+块渲染 | `chunk(blocks, viewport) → Chunk[]` / `compensateScroll(delta)` |
| `store` | 持久化 | `saveProgress(fileId, {blockIndex, ratio})` / `listRecent()` / `cacheLRU()` |
| `privacy` | 隐私授权封装 | `ensureAuthorized(apiName) → Promise<bool>` |

> **解析层纪律**：`detect` / `parse/*` / `sanitize` 必须写成**不依赖任何 wx API 的纯函数**。这样既能在 Worker 里跑（Worker 内无 `FileSystemManager`），也能在 Node 里直接跑测试语料——后者比在小程序里调试快一个数量级，直接决定 Phase 2/3 的开发速度。

## 6. 数据与持久化设计

- **文件本体**：`USER_DATA_PATH/files/{stableId}/origin.{ext}`（只读副本）。
- **抽取图片**：`USER_DATA_PATH/files/{stableId}/assets/…`（LRU 可清）。
- **索引/元数据**（key-value，注意 10MB 配额）：`meta:{id}`、`recent`（环形最多 N 条）、`progress:{id}`、`settings`。
- **LRU 清理**：启动时检查文件目录占用，超过阈值删除最久未用；进度保留。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| **Tailwind CDN 文档样式全丢** | **AI 文档最高频失败：页面塌成裸文本** | **ADR-10 内置类名规则生成器；Phase 3 门禁必须用 3 份真实 Tailwind 文档验收** |
| **`setData` 单次 1MB 超限** | 内容不显示、渲染失败 | 分块下发单次 < 64KB；base64 图片落盘（ADR-8）；节点树剔除渲染不需要的字段 |
| **虚拟滚动高度回填导致跳动** | 滚动时页面猛跳，难复现难定位 | 改动已渲染区域**上方**高度时同步反向补偿 `scrollTop`；专项测试 |
| **`mp-html` 的 CSS 支持不及预期** | 自研层工作量失控 | Phase 3 前用样例集实测定案（ADR-3），不凭想象决定边界 |
| **Worker 内无 `FileSystemManager`** | 数据流设计错误，实现卡死 | 主线程读+解码 → postMessage 传字符串 → Worker 纯计算 |
| 「用小程序打开文件」(scene 1173) 支持范围与主体限制未定 | 体验上限入口可能不可用 | Intake 抽象 + 官方文档核对；**chooseMessageFile 保底，验证不通不影响主流程** |
| GBK 探测误判 | 大面积乱码 | 手动编码切换 + 置信度提示 |
| 大文件/低端机崩溃 | 差评 | ADR-5 分层 + 真机性能测试门禁 |
| 复杂 CSS 还原差 | 阅读体验下降 | 阅读模式降级 + 语义优先（ADR-3.1 已明确 70–85% 上限） |
| 恶意 HTML | 安全/合规事故 | ADR-6 消毒 + 外链确认 |
| 包体积超限 | 无法提交 | 分包 + 构建期体积门禁 |
| 本地文件配额耗尽 | 文件打不开 | LRU + 明确报错引导清理 |
| **隐私保护指引未配置** | **接口调用直接失败，卡上线** | `__usePrivacyCheck__` + `wx.requirePrivacyAuthorize`，覆盖 chooseMessageFile 与剪贴板 |
| **审核员无文件可测** | **直接驳回** | 内置 3 份示例文档 + 首屏「查看示例」入口 |

## 8. 里程碑（与构建说明书对齐）

- **M1 可用的 TXT 阅读器**：intake + detect + txt 渲染 + 设置 + 进度。
- **M2 完整 Markdown**：md 解析渲染 + 目录 + 搜索 + 代码高亮。
- **M3 完整 HTML 阅读模式**：消毒 + HTML 渲染 + 图片 + 降级。
- **M4 加固与提审**：大文件性能、安全回归、真机兼容、审核材料。
