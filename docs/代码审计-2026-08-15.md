## 最严重的三条

### 1. 英文/代码/JSON 文件超过约 100KB 就打不开

`String.fromCharCode.apply(null, bigArray)` 的实参个数受调用栈限制，
V8 大约 12.5 万个就爆。解码器对连续 ASCII 段做批量转换时正好踩上：

```js
// 修复前
parts.push(String.fromCharCode.apply(null, bytes.subarray(chunkStart, i)));
```

实测 3MB 纯 ASCII 直接 `Maximum call stack size exceeded`，
异常一路冒到 `intake.loadFile` 的 catch，用户看到「文件加载失败」。

**讽刺之处**：中文文档反而没事——ASCII 段被汉字打断了，每段都很短。
所以这个缺陷在中文场景下测不出来，但英文文档、源码、JSON、CSV、日志全中。

修复：批量转换一律按 8192 字节分片。

### 2. `stableId` 根本不稳定

```js
// 修复前
var ts = Date.now().toString(36);
var rand = Math.random().toString(36).slice(2, 8);
return ts + rand + hash;
```

一个叫 stableId 的东西掺了时间戳和随机数。后果连锁：

- 阅读进度按 id 存 → **同一个文件每次打开都是新 id → 进度永远恢复不了**
- 「最近」按 id 去重 → 同一文件反复堆积
- 本地副本按 id 建目录 → **每打开一次多存一份完整副本，直到 200MB 配额耗尽**

E1「阅读进度」是 P0，实现层面是彻底失效的。
修复：id 只由「文件名 + 大小 + 内容指纹」决定。

### 3. 虚拟滚动的可见范围计算是 O(n)，而且算错

`computeVisibleRange` 每次滚动把全部块**线性扫三遍**，每块现算一次
`estimateHeight`（而 `estimateHeight` 每次调用都 `Object.assign` 一个新对象）。
函数开头还有一段完全是死代码的循环——里面的 `if` 是空的。

10 万块文档实测 **2.65 ms/次**。16ms 的帧预算里，光算范围就占掉 16%，
setData 还没开始。滚动必掉帧。

同时有三个正确性缺陷：

- `updateHeight` 计算块顶端位置时，把未测量的块按高度 0 计入，
  于是 `blockTop` 严重低估、**几乎恒判为「在视口上方」**——
  视口下方的块变高时也去补偿 scrollTop，**正是 D13 要防的那种页面猛跳**；
- `updateVisibleRange` 在可见范围没变时直接 return，
  注释写着「只更新 spacer」却什么都没更新，占位高度停在旧值；
- `getRenderData` 算底部占位时无视 heightCache 现算预估高度，
  与按 heightCache 算出来的 totalHeight 口径不一致，一有块测出真高就开始偏移。

修复：换成树状数组（前缀和 + 树上二分），`offset` / `indexAt` / `setHeight`
全部 O(log n)。实测 **2.65 ms → 0.001 ms（约 2600 倍）**，建索引一次性 9ms。

树状数组带来一个新的坑，也一并处理了：前缀和是逐段累加的，
正好停在某块顶端时两侧会差几个浮点末位，`indexAt` 会落到前一块——
表现是「保存进度 → 恢复进度」**稳定往前漂一整块**。已在 `indexAt` 和
`layoutToProgress` 各加一次精确校正，并写了往返测试。

## 分层清单

### 编码层（`core/encoding`、`core/detect`）

| 缺陷 | 表现 |
|---|---|
| `fromCharCode.apply` 爆栈 | 见上，>100KB 连续 ASCII 全挂 |
| `decode()` 对 UTF-16 多跳 2 字节 | **首字符恒定丢失**（有无 BOM 都丢） |
| UTF-16LE 代理对做了多余换算 | `A😀B` 解出来是 `𯘀B`，emoji 全错 |
| GB18030 四字节 BMP 用 `linear + 0x80` | 只在第一个区间内对，U+00A5 起整体错位 |
| GB18030 补充平面首字节限死 0x81–0x84 | 实际是 **0x90–0xE3**，emoji / CJK 扩展 B 完全解不出来 |
| 两字节码表用 `gbk` codec 生成 | gb18030 比 gbk 多约 2100 个双字节码位，全变 U+FFFD |
| 多字节分支 `continue` 跳过缓冲刷新 | 纯中文文档会把整篇拼进一个字符串 |
| Node 侧 `new Uint16Array(buf.buffer, buf.byteOffset, …)` | Buffer 走内存池，byteOffset 不保证 2 字节对齐，会 RangeError |
| `isBinary` 实现了但从未被调用 | B14 形同虚设 |
| `metaCharsetText` 参数从未被传过 | **B15（`<meta charset>` 优先级仅次于 BOM）整条规则空转** |
| `hasCJK` 用 `bytes.some()` 扫全量 | 纯英文大文件要把几十 MB 全扫一遍才得出 false |

GB18030 的四字节 BMP 区间表（206 段）现在由
`scripts/gen_encoding_tables.py` 从 **Python 官方 gb18030 codec** 生成，
测试语料同样由官方 codec 生成（`scripts/gen_encoding_fixtures.py`），
所以 `tests/test-encoding.js` 是**与权威实现对拍**，不是自证。
四字节 BMP 区做了**全量遍历**，不是抽样。

### 文本解析层（`core/parse`）

HTML 侧有完整的防炸弹上限（`MAX_NODES` 50000、`MAX_DEPTH` 100、
`MAX_BLOCKS`、`MAX_TOTAL_TEXT`、`MAX_IMAGES`）。
**TXT / Markdown / 代码 / JSON 侧一条都没有。**

| 缺陷 | 表现 |
|---|---|
| 文本侧无任何解析上限 | 违反 §2.4；50MB txt → 上百万个 block |
| B13 超长单行从未截断 | minified 一行几 MB，正则和 setData 双双爆炸 |
| `parseJson` 整份塞进单个 block | 10MB JSON → 20MB 单块，直接撞 setData 上限 |
| **Markdown 路径不做 BOM / 零宽清洗** | **首个标题失配变普通段落**——B2/B16 只在 TXT 路径做了 |
| 引用/脚注定义在代码块内也被抽走 | 代码示例里的 `[foo]: url` 凭空消失 |
| 列表续行直接跳过 | **续行内容丢失**，违反「降级不丢内容」 |
| 列表层级按 `indent/2` | 4 空格缩进的文档每级算两级，缩进翻倍 |
| `parseCode` 不归一换行 | CRLF 文件每行尾留一个 `\r` |
| `parseCode` / HTML 代码块存重复的 `raw` | 与 `text` 内容一致，setData 传输量白白翻倍 |
| TXT 短行标题启发式过宽 | `const a = { b: 1 };` 被判成章节标题 |

### 渲染层（`core/render`）

见「最严重的三条」第 3 条。

### 接入与存储层（`core/intake`、`core/store`）

| 缺陷 | 表现 |
|---|---|
| `stableId` 不稳定 | 见上 |
| **整份 `readFile` 进内存** | **直接违反 §2.6「大文件禁止一次性 readFile」**，且无任何体积闸门 |
| `readFile({length: 8192})` 不钳大小 | 小于 8192 字节的文件在部分平台直接 fail，**小文件反而打不开** |
| 配额写满无兜底 | G4 说的「LRU 清理 + 明确引导」没落地 |

| `removeFile` 不清「最近」条目 | 列表里留着点不开的死项 |
| 空文件无专门处理 | 只落到通用的「暂无内容」 |

### 页面层（`pages`、`app.js`）

| 缺陷 | 表现 |
|---|---|
| **粘贴内容无条件落盘** | **违反 E10**。剪贴板里常是刚复制的敏感内容，静默写盘并登记「最近」是隐私事故 |
| scene 1173 用一次性开关去重 | 同一启动周期内连开第二个素材，**完全没反应** |
| `openWithSystem` 里 `file.name.lastIndexOf` | `file.name` 缺失时直接抛异常 |
| `chooseMessageFile` 传了 extension 白名单 | 无后缀 / `.TXT` / `.tar.gz.txt` 在选择器里灰掉，与 A4/A5「内容嗅探优先于扩展名」自相矛盾；`handleSelectedFile` 里的 Office/压缩包分流因此永远走不到 |
| 「最近」不校验文件是否还在 | 点进去一片空白 |
| 搜索结果数无上限 | 大文档搜高频词，几万条 snippet 一次性 setData 超限，页面什么都不显示 |
| 三条加载路径各写一遍同样的 then | 改一处漏两处 |
| 内置示例文档有两套且已分叉 | `assets/samples/` 三份文件从未被读取，reader 里另有硬编码一套；F7 是 P0 提审门禁 |
| 消毒提示信噪比 | 剥掉 `<meta charset>` 也报「已移除不安全内容」，真有脚本时反而看不出来 |
| 滚动节流只在窗口开头取位置 | 16ms 后用的是过时的 scrollTop，快速滑动时可见范围落后 |
| 多文档解析结果无上限缓存 | D20 的内存累积 |

## 唯一未完成项：Worker 解析

`miniprogram/workers/parser.js` 至今是 **Phase 0 占位**，
`parseAndRender` 仍在主线程同步解析。§2.6 和 D18 都明确要求解析放 Worker。

**为什么没在这轮做掉**：Worker 是独立代码包，`workers/` 下的文件
只能 require `workers/` 内部的文件，无法 require `../core/parse/`。
落地必须二选一：

1. 加构建步骤，把 `core/parse`、`core/sanitize`、`core/detect` 复制进 `workers/`
   （解析层已经是纯函数，复制过去可直接跑；注意 Worker 包 ≤ 2MB，码表不能带进去）；
2. 把解析层的物理位置移到 `workers/`，主线程反过来从那里 require。

两条路都要动目录结构和构建流程，是独立的一次改动，
不该混在这轮缺陷修复里。已在 `docs/verify-notes.md` §13.5 写明。

**本轮的缓解**：`parseAndRender` 先让出一次事件循环再解析。
setData 是异步的，紧跟同步解析的话「正在解析文档...」这一帧根本没机会渲染——
用户看到的是一个卡住不动的旧界面。现在至少 loading 态是真的画得出来。

**待真机验证**：主线程解析 5MB Markdown 的实际耗时，据此决定 Worker 化的紧迫程度。

## 追加：真机白屏排查（同日）

真机打开白屏、模拟器正常。以下是静态排查出的全部问题，按「是白屏主因」的可能性排序。
**我没有设备，无法确认到底是哪一条**——但每一条都是真 bug，都已修。

### 高度可疑（能独立造成白屏）

**1. `app.json` 里 `supportedMaterials[].path` 是 `"pages/index/"`，不是合法页面路径。**
`pages` 里声明的是 `pages/index/index`。真机对 app.json 的校验比模拟器严，
配置非法会导致启动直接失败——表现就是白屏。已改为 `pages/index/index`。

**2. 全屏 flex 布局塌成 0 高。**
`.page` 是 `min-height:100vh; display:flex; flex-direction:column`，
子元素 `.content` / `.reader-scroll` 是 `flex:1; height:0` 的 scroll-view。
父容器高度是 `auto`（`min-height` 只是下限）时，这个弹性项在部分 WebView 里会解析成 0 高。
导航栏是 `position:fixed`，照常画出来；正文整块不见——**正是「打开一片空白」**。
模拟器按规范把 `min-height` 计入弹性布局，所以复现不出来。
已把 `.page` 改成确定的 `height:100vh`。

### 其余同时修掉的真 bug

**3. 首页图标全部不可见。** `index.wxml` 用了 8 个私有使用区码位
（`&#xe600;`–`&#xe60a;`）当图标，而**项目里根本没有 `@font-face`**。
iOS 上渲染成空白，安卓上是豆腐块。`reader.wxml` / `settings.wxml` 用的都是真实
Unicode（`←` `📖` `✕`），只有首页是这种写法。已统一成真实字符。

**4. 深色 / 护眼主题从来没生效过。** `app.wxss` 写的是 `page.theme-dark`——
WXSS 里的 `page` 指页面根元素本身，但主题 class 是 setData 到
`<view class="page {{themeClass}}">` 上的，那是 page 的**子节点**，选择器永远匹配不上。
（`reader.wxss` 里的 `.theme-dark .code-tok-*` 用的是类选择器，
说明 app.wxss 那两条才是写错的那个。）已改成类选择器。

**5. `index.js` 是全项目唯一用可选链 `?.` 和对象展开的文件。**
首页是入口，一旦命中未转译的运行时，整个文件解析失败 = 白屏，而且模拟器复现不出来。
其余文件清一色 `var` + `function`。已改回 ES5 安全写法。

**6. `onLaunch` 里 `wx.navigateTo` 跳阅读器。** 那个时刻页面栈还是空的，必然失败——
scene 1173「从聊天点开文件」这条路要么没反应，要么把用户扔在白页上。已改为等首页起来再跳。

**7. `onLaunch` 无异常兜底。** 其中任何一步抛异常，后面的初始化全断，
而每个页面都依赖 `globalData.settings` / `systemInfo`——结果是整个小程序白屏。
已逐步加 try/catch，并给 `systemInfo` 兜底默认值。

**8. `applyThemeNav` 在 `onLaunch` 调用 `wx.setNavigationBarColor`。**
页面栈为空时必然 fail。已挪到 `App.onShow` 并加 `fail` 回调。

**9. 移除 `componentFramework: "glass-easel"` 和 `renderer: "webview"`。**
这个项目一个自定义组件都没有（`components/` 全是空目录），
glass-easel 零收益却引入一整类渲染差异；`renderer: webview` 本来就是默认值。纯风险，删掉。

### 结构性措施：让白屏不再无声

- `App.onError` / `onUnhandledRejection` / `onPageNotFound` 全部接上，
  致命错误直接 `wx.showModal` 摆到用户面前，并提供「复制详情」。
  文件接入整条链路都是 Promise，漏接的 reject 以前只会表现为白屏或永久 loading。
- 新增 `tests/test-page-wiring.js`（35 条）——**页面装配静态检查**：
  app.json 页面文件是否齐全、`supportedMaterials.path` 是否合法、
  WXML 绑的事件处理函数 JS 里有没有、WXML 引用的数据字段 data 里有没有声明、
  有没有在缺字体时用私有区图标、主题选择器写法、全屏 flex 是否给了确定高度、
  有没有用需要转译的新语法。

  这套检查**逐条注入 bug 验证过确实会失败**（不是摆设）：
  path 改回 `pages/index/`、选择器改回 `page.theme-dark`、
  `height` 改回 `min-height`、加一个 `?.`、删一个事件处理函数——五种注入全部被抓到。
