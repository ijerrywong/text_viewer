# 隐私说明

> 本文件是本项目隐私相关的**唯一口径来源**。
> 后台《用户隐私保护指引》、提审说明、小程序内的授权弹窗文案，全部以此为准。
> 改动本文件时，同步检查 `docs/提审说明.md` 与 `miniprogram/pages/index/index.wxml` 的弹窗文案。

---

## 一句话立场

**用户的文件和剪贴板内容只在这台手机上被解析和渲染，不上传、不外发、不留副本给任何第三方。**
本项目零后端——没有自建服务器、没有云函数、没有数据库、没有对象存储，
技术上不存在"上传到哪里"这件事。

> **一处要讲清楚的例外：文档里的外链图片。**
> 文档若引用了图床上的图片（Markdown 里极常见），这些图片由**你的手机直接向那台图片服务器**取回。
> 它**不涉及上传你的文档内容**，但会让那台服务器知道你的 IP、以及你在看这张图。
> 2026-08-27（ADR-13）起此项**默认开启**——默认关闭会让引用图床的文档大面积丢图。
> 不接受的话，「设置 - 网络图片」一键关掉，关掉后全部格式的外链图都显示占位。

## 一、为什么声明里写着「收集」，而你说不上传？

这是最容易引起误会的一点，先讲清楚。

微信的隐私声明体系是**按接口管的，不是按数据流向管的**。
只要调用了能接触到用户数据的接口，无论拿到之后做什么——哪怕下一行就丢弃——都必须声明。
它声明的是「**我有能力接触到这类数据**」，不是「我会把它传走」。

原因很实际：微信无法验证一个小程序拿到数据后做了什么，能管控的只有接口边界。

因此会出现这样的组合，而且它是合理的：

| 微信要求声明 | 本小程序实际做的事 |
|---|---|
| 收集你选中的文件 | 把文件读进内存解析成文档结构，渲染到屏幕上；副本只存在这台手机的小程序沙盒里 |
| 读取你的剪切板 | 用户点「粘贴」时读一次剪贴板文本，渲染出来；**默认不写入磁盘** |

「收集」在这里的准确含义是：**文件从微信的领地进入了本小程序的沙盒**。
用户在微信文件选择器里选中文件后，微信会把它复制一份到小程序的临时目录——
这个动作本身就叫"收集"，与后续是否上传无关。

> 声明项的名称是微信给定的固定条目，措辞改不了。
> 能解释的位置有三处，本项目三处都用上了：
> 后台指引正文（见第三节）、小程序内的自定义授权弹窗（见第五节）、提审说明。

## 二、完整数据清单

**没有列在这张表里的数据，本小程序不接触。**

### 2.1 用户内容

| 数据 | 来源 | 存在哪 | 存多久 | 会不会离开设备 |
|---|---|---|---|---|
| 选中的文件正文 | `wx.chooseMessageFile` | `USER_DATA_PATH/files/{id}/origin.*` | 直到用户清除缓存，或被 LRU 按容量淘汰 | **否** |
| 文件里抽出的内嵌图片 | 文件自身的 base64 图片 | `USER_DATA_PATH/img_cache/` | 同上 | **否** |
| 粘贴的文本 | `wx.getClipboardData` | **默认只在内存中，不落盘** | 退出阅读页即消失 | **否** |
| 用 Office/PDF 打开的临时副本 | `wx.chooseMessageFile` | `USER_DATA_PATH/temp_open.*` | 下次打开同类文件时覆盖 | **否**（交给微信原生查看器） |

> 粘贴内容默认不落盘是有意为之：剪贴板里常常是刚从别处复制的敏感内容
> （聊天记录、口令、私密文档），静默写进磁盘并登记到「最近」是隐私事故。
> 需要保留时，阅读页提供显式的「保存到最近」按钮，由用户自己决定。

### 2.2 本地存储的元数据

存在小程序 key-value 存储里，**不含正文**：

| key | 内容 |
|---|---|
| `meta:{id}` | 文件名、大小、格式、编码、本地路径、打开时间 |
| `recent` | 最近打开的文件列表（同上字段，最多 50 条） |
| `progress:{id}` | 阅读进度：块索引 + 块内比例 + 保存时间 |
| `settings` | 主题、字号、行距、字体、网络图片开关、屏幕常亮 |

### 2.3 不收集的东西

- 不收集微信账号信息：**没有调用 `wx.login`、`wx.getUserProfile`**，拿不到 openid、昵称、头像
- 不收集位置、通讯录、相册、麦克风、摄像头
- 不收集设备标识用于追踪
- 不做埋点、不接统计 SDK、不接广告 SDK
- 不建立用户画像

## 三、后台《用户隐私保护指引》填写内容

> 位置：mp.weixin.qq.com → 设置 → 服务内容声明 → 用户隐私保护指引
> 这是**开发者侧的一次性配置**，用户在手机上无法自行解决。
> 不配置的后果：所有用户调用相关接口直接失败，且连授权弹窗都不会出现。

### 3.1 需要勾选的声明项

| 声明项 | 对应接口 | 处理目的（可直接填入） |
|---|---|---|
| **收集你选中的文件** | `wx.chooseMessageFile` | 用于读取你主动选择的文件内容，在你的设备本地完成编码识别、解析与排版渲染，使你能够在微信内阅读该文件。文件仅保存在本机的小程序存储空间中，不会上传至任何服务器，你可随时在「设置 - 清除缓存」中删除。 |
| **读取你的剪切板** | `wx.getClipboardData` / `wx.setClipboardData` | 仅在你主动点击「粘贴文本」时读取一次剪贴板中的文本内容，用于在本机渲染阅读；粘贴内容默认不写入存储，退出阅读页即释放。在你点击「复制链接」或「复制代码」时写入剪贴板。全过程不上传任何服务器。 |

### 3.2 第三方共享

**无。** 本小程序不使用任何第三方 SDK，不向任何第三方提供用户信息。

### 3.3 数据存储与删除

- 存储位置：仅用户本机（小程序文件存储 + key-value 存储）
- 存储期限：由用户控制，可随时在「设置 - 清除缓存」删除全部本地文件
- 自动清理：本地文件占用超过阈值时按最久未使用顺序自动清理
- 删除方式：设置页「清除缓存」；或删除小程序（微信会一并清除其全部本地数据）

## 四、承诺与代码的对应关系

隐私承诺如果无法验证，就只是一句话。下面每条承诺都能指到具体代码：

| 承诺 | 由什么保证 | 位置 |
|---|---|---|
| 不上传任何内容 | 全项目**没有任何网络请求代码**：无 `wx.request` / `uploadFile` / `downloadFile` / `connectSocket`，无云函数。文档里的外链图片由 `<image>` 组件按 `src` 自行取回，不经过我方任何代码，也不携带文档内容 | 可全局搜索验证 |
| 不使用 web-view | 个人主体不可用，且规定永不生成相关代码 | `AGENTS.md` §2.3 |
| 粘贴内容不落盘 | 只存内存，落盘需用户点「保存到最近」 | `reader.js` `loadClipboardContent` / `saveClipboardToRecent` |
| 网络图片可一键关掉 | 默认开启（ADR-13），开关旁明示隐私影响；关闭后 md / html / txt 全部格式的外链图都显示占位，且当场生效 | `app.js` `DEFAULT_SETTINGS.networkImages = true` / `reader.js` `applyNetworkImageGate` / `tests/test-network-images.js` |
| 外链绝不静默跳转 | 点击 → 弹窗显示完整 URL → 用户确认后仅复制到剪贴板 | `reader.js` `onLinkTap` |
| 文件名不外泄路径信息 | 磁盘上一律以 `stableId` 命名，原始文件名只存元数据 | `intake.js` `sanitizeFileName` / `copyToUserDir` |
| 不获取微信身份 | 无 `wx.login` / `wx.getUserProfile` 调用 | 可全局搜索验证 |
| 剥离危险内容 | HTML 消毒剥离 script/iframe/on*/javascript: 等 | `core/sanitize/index.js` |

> **为什么网络图片是个隐私话题**：`<image>` 的 src 不受合法域名白名单限制，
> 技术上可以加载外链图；加载时会向图片所在的第三方服务器暴露用户的 IP 与阅读行为。
> 曾经的做法是默认关闭，ADR-13 改为默认开启——理由是目标场景（手机端临时阅读微信里收到的文本）
> 私密性普遍不高，而默认关闭的代价是引用图床的文档大面积丢图，这个代价是实打实的。
>
> 但**默认开启之后，这个开关就是有隐私诉求的用户唯一的关掉方式**，因此对它的要求反而更高了：
> 必须覆盖全部格式、必须当场生效、必须给出可见的占位而不是空白。三条都有回归测试钉着。

## 五、小程序内的文案口径

三处文案必须与本文件一致，改一处要同步其余两处。

### 5.1 授权弹窗（`pages/index/index.wxml`，已实现）

> 本小程序所有文件均在你的手机本地解析渲染，全程不上传任何服务器，无云端存储。
> 选择文件和读取剪贴板需要你的授权。

### 5.2 剪贴板标注（已实现，2026-09-13 改位置）

`AGENTS.md` §1.1 与 Edge E9 要求粘贴入口标注「仅读取一次，不会上传」。
措辞现在放在首页页尾的隐私脚注里，和另外两条隐私说明排在一起：

> 文档在本机解析，内容不上传服务器
> 剪贴板只在你点「粘贴文本」时读一次，不上传
> 文档里的网络图片由你的手机直接加载，可在设置中关闭 ›

**为什么不再放在卡里**：它此前是粘贴卡的第三行小字，使这张卡比另外两张入口卡
高出一截 —— 三张并列的卡不是同一个矩形，违反重复原则。
**代价要如实记下**：脚注在首屏之下，用户点「粘贴文本」之前很可能没读到它，
E9 所说的「按钮旁」这一层已经不成立；标注仍在页内，但预防作用弱于原方案。
真机验证若发现 iOS 剪贴板提示引起的投诉，优先考虑的补救是点按时先给一次
`wx.showModal` 说明，而不是把小字塞回卡里（那会再次破坏卡片等高）。

价值不低：iOS 读剪贴板会弹系统级提示「XX 读取了你的剪贴板」，这个挡不住。
提前标注能显著降低"被偷看了"的观感。

### 5.3 设置页的网络图片开关说明（已实现）

> 网络图片
> 加载文档里的外链图片。会向图片服务器暴露 IP 与阅读行为，关闭后显示占位

默认开启（ADR-13）。措辞不再是"开启前的警告"，而是**中性的事实陈述 + 指出关掉之后会怎样**——
默认值翻转后，需要被告知的是「怎么关、关了什么样」。

## 六、明确不做的事

这些不是"暂时没做"，是**设计上排除**的：

- ❌ 不做文件上传、云端存储、跨设备同步
- ❌ 不做文件转发、分享链接、生成外链
  （微信明确禁止无资质的网盘类小程序；分享仅限小程序卡片，对方点开需自己选文件）
- ❌ 不做账号体系、不做登录
- ❌ 不接入任何统计、广告、崩溃上报 SDK
- ❌ 不做内容审核上报（无上传、无 UGC、无云端存储，因此无内容审核义务）
